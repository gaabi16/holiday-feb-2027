# Family holiday document — February 2027

## What the project is

A static page hosted on GitHub Pages, read by 4 family members choosing a
destination: Mark, Mum, Dad, Alex. They are not technical. **The document is in
English** — it used to be in Romanian and was translated in full, code comments
included, so do not reintroduce Romanian anywhere.

Its purpose: put several destinations and flight options side by side, with
prices and connection risks, so a decision can be made without anyone opening
Skyscanner.

## Layout of the repository

```
src/                    the content, one file per destination
  head.html             doctype, <head>, opening <div class="wrap">
  header.html           title and intro line
  dest-01-manila.html   … through dest-08-zanzibar.html
  footer.html           the empty-slot note, footer, closing tags, <script> tags
build.mjs               assembles src/ into index.html
index.html              GENERATED — never edit it by hand
style.css               all the styling, variables in :root
globe/
  land-data.js          the LAND blob, generated by make-globe.mjs
  routes.js             ROUTES: airport coordinates and segment durations
  engine.js             the orthographic projection and canvas drawing
make-globe.mjs          regenerates globe/land-data.js
```

**Edit `src/`, never `index.html`.** After any change under `src/`:

```
node build.mjs
```

The build concatenates the partials in filename order (the `dest-NN-` prefix is
what orders the page) and stamps today's date into the `?v=` cache-busting
parameter on `style.css` and the three globe scripts. Without that stamp the
browser serves a stale CSS or JS and the page looks broken — it has happened
before: tab C showed nothing because the cached CSS had no rule for it.

The output is a single self-contained `index.html`, so the document still opens
straight off the disk with a double-click. No framework, no bundler, no
transpiling — the build is a concatenation and nothing more. Keep it that way.

## How I work on it

Mark sends screenshots from flight sites. I pull the data out of them and add it
to the document. I do not invent prices or schedules that are not in the sources.

Rules he asked for explicitly:

- **Short.** He has already rejected one version for being too long. Each
  destination is a collapsed `<details>`. Closed, ten destinations must fit on
  one screen.
- **All sums in EUR**, but with the actual payment currency named on each
  segment. Rate used: 1 € = 5.25 RON, 1 € = 4.26 AED (6 September 2026). It is
  written in the footer.
- **Total for 4 people and the per-person figure**, always both.
- **Nights that need accommodation en route marked explicitly** — they are a
  hidden cost and they matter in the comparison. In HTML they are `.stay` blocks.
- **Risky connections marked** — the `.gap .risk` blocks. Separate tickets plus a
  terminal change is a real risk and gets written as one.
- No long disclaimers, no repeating the same figures in two places.

Numbers follow English conventions: `€2,387` with a comma for thousands, `€199.96`
with a dot for decimals, `RON 824` rather than `824 lei`, dates as `Saturday 13 Feb`.

## Look

Flight-tracker aesthetic, asked for explicitly: dark navy background, night-side
globe, amber route. The variables are in `:root`. Font: IBM Plex Sans, with IBM
Plex Mono for times, airport codes and prices.

## The globes

Interactive canvases drawn by `globe/engine.js`: they rotate by dragging with the
mouse or a finger, zoom from the `+` / `−` buttons (the wheel only works after a
click on the globe, otherwise it would steal the page scroll; pinch works on a
phone), and each stretch of the route carries the flight duration. Hand-written
orthographic projection, no libraries, centred automatically on the middle of the
route.

**A new destination needs no Node beyond the build.** Add the route to `ROUTES`
in `globe/routes.js` and put a `<div class="globe" data-route="route-code">` with
its canvas and buttons into the destination's `src/dest-*.html` (copy the block
from Manila). A route has:

- `points` — the airports in flight order, with `lon`, `lat`, `code`;
- `spans` — the duration labels, each covering the stretch from `from` to `to`;
- `ground` — optional, the indices of the arcs that are surface transport
  (bus/taxi) rather than flights; they are drawn teal instead of amber.

Labels carry digits only — the flight duration and the layover — with no "out" or
"back", because the direction reads from the column on the right anyway.
Durations are written only when they appear in the sources; where we only have
the total time of a connection with a layover, the label covers the whole span
(`{from:1, to:3}`) rather than being split across segments. Each label places
itself on the longest stretch of its span and on the freer side of the line, so
it does not fall across the airport codes. Every label looks for the spot with
the least overlap against what is already drawn — without that, airports close
together (Brussels-Zaventem and Charleroi are 46 km apart, Abu Dhabi and Dubai
116 km) end up with their labels on top of each other.

A route can close on itself, with `points` starting and ending at the same
airport — that is how Bangkok looks, where the outbound and the return take
completely different paths. The repeated airport code is written only once.

`ground` segments are drawn teal (`#3ddbd9`), a solid line with the same glow as
the flights — clearly not a flight, but not faded out either. A span with
`ground:true` gets the same colour on its label.

The coastlines are encoded compactly in `LAND` in `globe/land-data.js` (~11 KB,
between the `LAND-DATA` markers). Regenerate only if you want a different
resolution:

```
npm install world-atlas topojson-client
node make-globe.mjs
```

The script rewrites that block on its own.

## The shape of a destination

```
<details class="dest">
  <summary>  name, dates, price per person, total  </summary>
  <div class="body">
    table .compare        — only when there are several flight options
    .tabs                 — radio + CSS tabs, no JS, one pane per option
      .split              — globe on the left, .route on the right
      .grid2              — cost + how we cut it
      .grid2              — worth knowing + to check
    .alert                — a risk that applies to every option
  </div>
</details>
```

Each destination with tabs needs its **own set of ids** in `style.css`, because
the `#id:checked ~ .pane-x` selectors only work between siblings. In use so far:
`va`…`ve` (Manila), `ba` / `bb` / `bc` (Bangkok), `sa` / `sb` / `sc` (Ho Chi Minh).
